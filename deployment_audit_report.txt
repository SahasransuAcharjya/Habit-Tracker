=== CRITICAL ISSUES (Must Fix Before Deployment) ===
1. [EMPTY .GITIGNORE & LEAKED SECRETS]
   - File: /.gitignore (Line 1)
   - Issue: Root `.gitignore` is completely empty (0 bytes). Confidential database credentials, JWT secrets, and VAPID private keys in `backend/.env` (`postgresql://postgres:KSAcharjya@047...`) risk being committed to public version control.
   - Fix: Populate `.gitignore` with `.env`, `.env.local`, `node_modules/`, `.next/`, `dist/`, and scratch files. Immediately rotate the database password and VAPID keys.

2. [HARDCODED FALLBACK JWT SECRET]
   - File: backend/src/config/env.js (Line 9)
   - Issue: `jwtSecret` falls back to `"dev_jwt_secret_change_me"`. If `JWT_SECRET` is omitted in production environments, tokens will be signed with a known weak secret, allowing arbitrary JWT forgery.
   - Fix: Throw a fatal error on backend startup if `process.env.JWT_SECRET` is undefined or empty when `NODE_ENV === "production"`.

3. [EXPOSING INTERNAL ERROR STACKS & MESSAGES TO CLIENTS]
   - File: backend/src/middleware/authMiddleware.js (Line 26) & backend/src/middleware/errorMiddleware.js (Line 10)
   - Issue: `authMiddleware` returns `error.message` in 401 JSON responses, exposing detailed JWT verification/parser errors. `errorMiddleware` prints full error stacks when `NODE_ENV !== "production"`.
   - Fix: Sanitize error responses sent to client callers; log detailed error details server-side only.

4. [NEXT.JS MIDDLEWARE NAMING INCOMPATIBILITY]
   - File: frontend/src/proxy.ts (Line 4)
   - Issue: Next.js App Router expects `middleware.ts` at `src/middleware.ts` or root. Renaming it to `proxy.ts` prevents Next.js from automatically registering route protection middleware, leaving dashboard routes client-side accessible without token checks on initial server load.
   - Fix: Rename `src/proxy.ts` to `src/middleware.ts` and export default / middleware function properly.

=== HIGH PRIORITY ISSUES ===
1. [DIRECT FETCH CALLS BYPASSING API UTILITY & AUTH WRAPPER]
   - Files:
     - frontend/src/app/(dashboard)/tasks/create/page.tsx (Line 61)
     - frontend/src/app/(dashboard)/tasks/[taskId]/page.tsx (Line 44)
   - Issue: Pages make direct `fetch()` calls using `localStorage.getItem("activity_token")` instead of using the centralized `apiPost` / `apiGet` utilities from `src/lib/api.ts`. This bypasses unified error handling, base URL fallback, and authorization headers.
   - Fix: Refactor component fetch logic to use `apiGet`, `apiPost`, `apiPatch` from `@/lib/api`.

2. [SEQUENTIAL N+1 PROMISE EXECUTION IN CRON JOBS]
   - Files:
     - backend/src/jobs/generateDailyReportJob.js (Lines 19-27)
     - backend/src/jobs/sendReminderJob.js (Lines 40-48)
   - Issue: Cron jobs iterate sequentially over users with `for...of` loops performing database queries and web-push network operations one by one. As user count grows, job execution will block and time out.
   - Fix: Batch processing with chunked `Promise.all()` or delegate jobs to a dedicated message queue (e.g. BullMQ / Redis).

3. [HEALTH CHECK DOES NOT VALIDATE DB CONNECTIVITY]
   - File: backend/src/app.js (Lines 29-35)
   - Issue: `/api/health` returns `200 OK` statically without querying the database via Prisma (`prisma.$queryRaw` or `prisma.user.findFirst`). Load balancers will mark instances healthy even if database connectivity is completely lost.
   - Fix: Add a DB ping check inside `/api/health` and return `530 Service Unavailable` if database connection fails.

4. [ENVIRONMENT VARIABLE KEY MISMATCH IN DOCUMENTATION]
   - Files: README.md (Lines 62-63) vs backend/src/config/env.js (Lines 12-14)
   - Issue: `README.md` documents `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY`, but backend code reads `WEB_PUSH_PUBLIC_KEY` and `WEB_PUSH_PRIVATE_KEY`.
   - Fix: Align environment variable keys in `README.md` and `.env.example` with backend implementation.
